- **One entry per gap:** `- **<code>** — <what is wrong and where>. <owning package> [mechanical|architectural] — <evidence, prevention rung>`.

Next code: `G-ORBITAL-SHELL-PYTHON-010`

- **G-ORBITAL-SHELL-PYTHON-001** — [generated (ML) path only] Python shell has no query/write push-down and no `persist batch` (owner Q13 declared reason). `src/codegen/sexpr_to_py.rs`: `Fetch` emits `fetch(entity_type, filter, order_by, offset, limit)` and the backend lists then filters in-process; `OirEffect::PersistBatch` emits an `UNSUPPORTED operator: persist batch` marker carrying `PUSHDOWN_STATUS`. orbital-shell-python [architectural] — evidence: tests `ordered_filtered_fetch_stays_on_plain_path`, `persist_batch_fails_loudly_with_reason`. Prevention rung: none of the language rungs (tooling/perf); rule "no shell left on the full-table path without a declared reason" (docs/Almadar_Embedded_Kernel.md). Close by implementing push-down + batch here or retiring the shell's data path.
- **G-ORBITAL-SHELL-PYTHON-002** — [generated (ML) path only] The Python shell template's `EffectExecutor._execute_fetch` (`templates/python-shell/src/orbital_app/core/effect_executor.py`) ignores `offset`/`limit` and the `@read` policy; since EXEC-FETCH-1 it orders by the default or an authored `orderBy` only. `orbital-shell-python` [mechanical] — evidence: no window arguments read in `_execute_fetch`; prevention rung: `orb verify --shell python` fetch window case.
- **G-ORBITAL-SHELL-PYTHON-004** — [generated (ML) path only] The Python shell's generated fetch silently drops the `nearest` option (EXEC-FETCH-2): `src/codegen/sexpr_to_py.rs` `Fetch` emits a plain filtered list, so a `fetch nearest` returns unranked rows with no error. Close by emitting a refusing handler, or with Wave 10 (the shell embeds the kernel).
