Next code: `G-ORBITAL-SHELL-PYTHON-006`

- **G-ORBITAL-SHELL-PYTHON-005** — [owner-decision] A program that uses a Python-only (ML) operator cannot run on the native kernel, so the Python shell keeps the whole generated host for it (the generated traits, `sexpr_to_py`, the template `effect_executor.py` / `repository.py`, and G-ORBITAL-SHELL-PYTHON-001 to 004 all still apply to it). `orbital-shell-python` `kernel_host::choose` picks the host from the operator table (`auto`: the kernel unless a category with `target: ["python"]` alone is used). The ~100 operators (`ml-arch`, `ml-effect`, `ml-tensor`, `ml-graph`, `ml-contract`, `ml-data`, `std-nn`, `std-tensor`, `std-train`: `nn/linear`, `tensor/matmul`, `train`, `graph/*`, …) are pure expression operators backed by the torch helpers in `backend.rs` (`generate_nn_helpers` …); the kernel evaluator has no tensor type and its only host-delegation path is `IoRequest::Substrate{op,args}`, which it sends for substrate operators only. Option A: register the Python-only operators as program-host operators (`is_substrate_operator`), so the kernel asks the Python host through `Substrate{op,args}` and the torch helpers answer; this is a language change (operator table, `lower`, `orbital-core` eval) and must land on the JS runtime path too, and a tensor value crossing JSON loses its identity (a model handle needs a host-side registry the kernel never sees). Option B: ML programs stay on the generated host for good, two Python execution modes with the divergence risk 001 to 004 record; the host choice stays the structural check on the operator table. Decide A or B; until then B is what runs. Evidence: `kernel_host::tests::a_program_with_a_python_only_operator_keeps_the_generated_host`. Prevention rung: none of the language rungs (a product and language-surface choice).
- **G-ORBITAL-SHELL-PYTHON-001** — Python shell has no query/write push-down and no `persist batch` (owner Q13 declared reason). `src/codegen/sexpr_to_py.rs`: `Fetch` emits `fetch(entity_type, filter, order_by, offset, limit)` and the backend lists then filters in-process; `OirEffect::PersistBatch` emits an `UNSUPPORTED operator: persist batch` marker carrying `PUSHDOWN_STATUS`. orbital-shell-python [architectural] — evidence: tests `ordered_filtered_fetch_stays_on_plain_path`, `persist_batch_fails_loudly_with_reason`. Prevention rung: none of the language rungs (tooling/perf); rule "no shell left on the full-table path without a declared reason" (docs/Almadar_Embedded_Kernel.md). Close by implementing push-down + batch here or retiring the shell's data path.
- **G-ORBITAL-SHELL-PYTHON-002** — The Python shell template's `EffectExecutor._execute_fetch` (`templates/python-shell/src/orbital_app/core/effect_executor.py`) ignores `offset`/`limit` and the `@read` policy; since EXEC-FETCH-1 it orders by the default or an authored `orderBy` only. `orbital-shell-python` [mechanical] — evidence: no window arguments read in `_execute_fetch`; prevention rung: `orb verify --shell python` fetch window case.
- **G-ORBITAL-SHELL-PYTHON-004** — The Python shell's generated fetch silently drops the `nearest` option (EXEC-FETCH-2): `src/codegen/sexpr_to_py.rs` `Fetch` emits a plain filtered list, so a `fetch nearest` returns unranked rows with no error. The TS generated-handler path refuses it instead. `orbital-shell-python` [mechanical] — evidence: `sexpr_to_py::tests::fetch` has no nearest case; prevention rung: `orb verify --shell python` (a shell that cannot run an effect option must refuse it, not drop it). Close by emitting a refusing handler, or with Wave 10 (the shell embeds the kernel).
- **G-ORBITAL-SHELL-PYTHON-003** — The Python shell's `persist update` upserts and `persist delete` of an absent row reports success, against EXEC-STEP-8 (an update/delete of an absent row fails `not-found`; no row key fails `no-row-key`). `templates/python-shell/src/orbital_app/core/repository.py` `InMemoryRepository.update` creates the row when absent; `effect_executor.py` `_execute_persist` never sets `not-found`; the generated trait code (`src/generators/trait_generator.rs`) reports `success: bool(_update_id)`. `orbital-shell-python` [mechanical] — evidence: `InMemoryRepository.update` body; prevention rung: `orb verify --shell python` persist-code case (the shared `effect-codes/persist-codes.json`). Close by reading the row first and failing `not-found`, then pin it with that fixture.
